## 決定済み

| 日付 | 決定 | 理由 |
|---|---|---|
| 2026-10-15 | ユーザーは原作者。成果物は漫画家と編集者に渡すネーム画像 | 原作者は絵を描かないので、絵は AI が出す |
| 2026-10-15 | 生成の単位はコマ（2026-10-17 に一括生成はページ単位へ改めた） | ページ丸ごと生成するとコマ枠とフキダシの位置が守れない。コマ単位なら再生成の範囲も最小になる |
| 2026-10-15 | セリフとコマ枠とフキダシはアプリが描き、AI には描かせない | 日本語の文字生成は崩れる。セリフを直すたびに絵が変わるのも避ける |
| 2026-10-15 | レンダラは決定論的。キャンバスとは別実装 | 出力の再現性のため。キャンバスは編集用で、SVG と Canvas の差を許容する |
| 2026-10-15 | 生成画像はコマごとに履歴を残す | 修正ループで前の版に戻れないと困る |
| 2026-10-15 | 視線誘導診断は補助機能。生成プロンプトのヒントとオーバーレイに使う | 構図の意図を言語化する材料になる。必須にはしない |
| 2026-10-15 | AI 呼び出しは Workers 経由のみ | API キー配布回避、利用量制御の一元化 |
| 2026-10-15 | 筆圧、傾き、描画品質は要件外 | ネーム用途のため |
| 2026-10-15 | 手描き層から焦点を自動抽出しない | 画像認識を要件に入れると重い。手動で置けば十分 |
| 2026-10-15 | キャンバスは自前 SVG | 矩形と点とベクトルと画像だけなので外部ライブラリ不要 |
| 2026-10-15 | store は JSON Patch インターフェース | 共同編集の CRDT（Yjs）に呼び出し側を変えずに置き換えるため |
| 2026-10-15 | 座標は正規化 0..1 | ページサイズと DPI 非依存 |
| 2026-10-16 | 画像生成プロバイダは Google Gemini Nano Banana 2.1（`gemini-nano-banana-2.1`、1K 出力）。フィクスチャ Panel 4 の目視でモノクロ線画が出なければ OpenAI gpt-image-2.5 に替える | ネームに要るのは配置図どおりの構図とキャラの見分けで、参照画像を 14 枚（キャラ 4 枚）まで渡せる。1K が 1 枚 $0.034 で、1 コマ複数生成して選ぶ運用に耐える。有料枠は入力を学習に使わず出力の所有権を主張しない。FLUX.2 と Seedream はモノクロ線画の実績が薄く、Workers AI は入力 512px 未満で配置図が読めない |
| 2026-10-16 | フキダシ領域は配置図を参照画像として渡すだけ（#2 の (a)）。マスクは使わず、フキダシはアプリが絵の上にレイヤーとして重ねる | マスク画像を受けるのは OpenAI だけで、使うとプロバイダ選定が縛られる。配置図は元々渡すので追加コストがなく、白抜きが守られなくてもフキダシが上に乗るので致命的ではない |
| 2026-10-16 | LLM プロバイダは Anthropic Claude Haiku 5.5（`claude-haiku-5-5`）。脚本からの下書きの提案が 10 回中 9 回スキーマを通らなければ上位モデルに替える | 用途はざっくり提案してざっくり直すことなので値段で選ぶ。入力 $0.10 / 出力 $0.50（100 万トークンあたり）で最安帯、1 ページの提案が 1 円弱。構造化出力に対応する。同額の OpenAI GPT-6 Luna とはユーザーの好みで選んだ。Gemini Flash は約 7 倍高いので外した |
| 2026-10-16 | 認証は Better Auth を workers/api 上で動かし、ユーザーとセッションは D1 に置く（#3 の (a)）。最初は Google OAuth だけにする | D1 は既に使っていて、共同編集でプロジェクトとユーザーを同じ DB で引ける。ユーザー数課金がない。Clerk はユーザー情報が外に置かれ、Cloudflare Access はアプリのユーザー管理にならない。Google OAuth だけならメール送信を持たずに済む |
| 2026-10-16 | 画像の保存上限は 1 ユーザーのアセット合計 5GB。プロジェクト単位の上限は設けない。超えたらアップロードを 413 で拒否し、自動では消さない | 費用を決めるのはユーザー合計で、プロジェクトごとに分けても使い方を縛るだけ。1K の生成画像を 1 枚 1MB 前後と見て約 5000 枚。R2 の無料枠 10GB に収まり、超えても $0.015/GB/月。履歴を勝手に消すと前の版に戻れなくなる |
| 2026-10-16 | 共同編集はリアルタイム同時編集にする（#11）。ロールは owner / editor / commenter / viewer。招待は owner がメールアドレスとロールを指定して作り、出た招待リンクを owner が自分で渡す。そのメールアドレスで Google ログインした人だけが受け取れる | 同期（Yjs + Durable Object）は既にリアルタイムで動いている。招待メールを送ると #3 で避けたメール送信基盤が要る。招待先のメールアドレスと照合すれば、リンクが漏れても他人は参加できない |
| 2026-10-17 | 視線誘導の評価（診断オーバーレイ、読み順 OK と焦点の ok / weak / miss、診断の問題、AI に相談）をエディタに出さない。生成プロンプトのヒントは残す | 経路はコマ単位の centre sweep で、コマ同士の位置関係しか見ていない。読者の目はコマの中の顔など重要な要素に引かれるので、その評価として当てにならない。LLM に評価させても検証しにくく、費用に見合わない |
| 2026-10-17 | ページとエピソードの一括生成は、ページ 1 枚を 1 回で生成して各コマの枠の矩形で切り抜く。1 コマの生成と修正指示つきの再生成はコマ単位のまま。利用量はページ 1 回を 1 回と数える | コマごとに呼ぶとコマ同士で絵柄とキャラの見た目が揃わない。1 ページ 6 コマなら呼び出しが 6 回になり、費用と月間上限を 6 倍使う。コマ枠とフキダシの位置はページ全体の配置図で伝え、ずれても枠とフキダシはアプリが上に描くので致命的ではない。気に入らないコマだけコマ単位で作り直せるので、再生成の範囲は最小のまま。切り抜くとコマの解像度は 1K のページの一部になるが、ネームの用途では足りる。PanelArt はコマごとに切り抜きを持つので、データモデルは変えない |
| 2026-10-17 | a11y はコントロールの名前、キーボード操作、フォーカスの見た目、コントラストまでを守り、読み上げでの操作と見出しの構造は対象外にする | 編集の中心はキャンバスで、成果物は画像なので、読み上げで使える形にする費用に見合わない。名前と役割は e2e が要素を探すのに使い、iPad ではラベルを押してもコントロールに届く。キーボード操作とフォーカスの見た目はデスクトップの使い勝手でもある |
