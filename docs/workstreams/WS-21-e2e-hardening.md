# WS-21 e2e-hardening

Phase 2（Phase 1 統合後から継続）/ 開発中の依存: なし

## 目的
Playwright で主要フローを自動化し、リリース品質を維持する。

## シナリオ
1. プロジェクト作成 → ページ追加 → コマ分割 → フキダシ追加とセリフ入力 → コマ生成（Fake）→ PNG 書き出し → リロードで復元。
2. フィクスチャ JSON インポート → ページ一括生成（Fake）→ PNG 書き出し → レンダラのスナップショットと一致。
3. 修正指示つき再生成 → 履歴切替 → Undo。
4. PDF 書き出し → ページ数と見開き順の検証。
5. 診断オーバーレイ表示 → 集計行 → 焦点を動かして miss が出る。
6. 脚本から下書き（Fake）→ 追加 → Undo。
7. ログイン → クラウド保存 → 別ブラウザで開く。
8. Desktop: 起動 → ファイルを開く → 生成 → 保存（`tauri-driver`）。

## 付随
- Lighthouse でエディタ画面の TTI 計測。目標 3 秒以内。
- バンドルサイズ監視。エディタ初期ロード 500KB gzip 以内（フォントは遅延読み込み）。
- エラー監視（Sentry 等）の導入判断。

## 受け入れ条件
- [ ] 上記シナリオが CI で安定して通る（flaky 率 1% 未満）
- [ ] 失敗時にスクリーンショットとトレースが残る
